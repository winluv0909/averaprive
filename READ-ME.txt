AVERA PRIVE — WEBSITE REVIEW & PLATFORM SECURITY UPDATE

This update is based on your Avera Prive(3).zip. Keep all test accounts and records until the live checks have passed.

INSTALL
1. Back up your project and Supabase database. Keep the Supabase dashboard accessible.
2. Extract this ZIP into a separate folder, outside your project.
3. Stop npm run dev.
4. In a PowerShell terminal opened in your existing project folder (where package.json lives), run:
   & "C:\path\to\extracted\Install-Platform-Security.ps1"
   The installer backs up replaced files and records newly added files.
5. In the Avera Prive Supabase SQL Editor, run the full contents of:
   files/supabase/migrations/202610120027_platform_password_setup.sql
   Run once. This marks current platform accounts as needing password setup.
   It does NOT delete accounts or data. Do not run this migration repeatedly because it resets setup flags.
6. Restart npm run dev.
7. Use your current test platform owner login at /owners/login. You should be directed to /owners/account.
8. Enter its current/temporary password, then a DIFFERENT new password of 12-128 characters. Confirm it.
9. Sign in again. Dashboard access should now work. Account security lets you change it again later.
10. Open Staff accounts in the owner sidebar. Create a test moderator with a separate email and temporary password.
11. Sign out and use the moderator account. It must also change its password first. It should land in Moderation and must be denied owner-only Staff accounts, Directory management and Audit log.

OFFICIAL OWNERS
Create the two official Auth users in Supabase Authentication using their separate emails and temporary passwords. Send their User UIDs for the exact owner-role assignment SQL. Granting their first staff role after the migration marks them for first-login password setup automatically. The staff creation form cannot assign super_admin. Keep the test owner until BOTH official owners have verified access. There is no artificial staff count cap; Supabase service limits still apply.

PASSWORD RECOVERY
This update implements signed-in password changes and mandatory first-login setup. A public forgot-password email/recovery flow is not included and must be configured and verified separately before launch. For an administrator resetting a platform user to a temporary password in Supabase, re-enable platform_password_change_required in administrator-controlled app metadata AFTER resetting the password.

ROLLBACK
The installer prints a backup folder. Restore replaced files using ORIGINAL-FILES.txt. Remove only files listed in NEW-FILES.txt if rolling back. The SQL migration changes platform authorization: reverting source files alone does not revert the database setup gate. Complete password setup or ask the administrator for a coordinated rollback; do not weaken permission checks blindly.
